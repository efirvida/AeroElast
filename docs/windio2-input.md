## Reader boundary

`Blade.read_yaml` and `load_blade_aero` normalize supported windIO 2.0 blade
fields **in memory**. No converted YAML is written:

- Geometric twist and polar angles convert from degrees to the reader's radians;
  structural component fiber angles remain degrees.
- Dimensioned `section_offset_y` is divided by chord on the union of their grids.
- Explicit anchor arcs resolve recursively, including web-local anchors; plane
  intersections are not recomputed. V2 cap placement uses the full TE-midpoint
  perimeter, including both legs of an open trailing edge, as required by the
  pinned schema's `nd_arc_position` and construction guide. The suction-to-pressure
  coordinate is reversed (`1 - nd_arc`) for NuMAD's arc direction. Inherited web
  arc placement in legacy keypoints is not used by the v2 public mesh adapter.
- Layer thicknesses, material constants, chord knots and relative thickness are
  retained. Beam elastic-property tables do not replace laminate properties.
- windIO v1 bypasses normalization; its geometry construction is unchanged.

This is **not** a complete windIO 2.0 implementation. Weighted airfoil blends,
nonzero `section_offset_x`, missing explicit anchor arcs, cycles and unsupported
versions raise errors rather than silently selecting another physical model.

## V2 section frames

The v2-only frame path follows the pinned construction guide, lines 82–103.
Native reference-axis PCHIP curves supply both positions and analytical tangent
vectors at each output station, including inserted chord knots. Reference-axis
translation includes the root coordinates; it is applied after section rotation.

In windIO axes, solve `(My @ Mx) ez = t` on the forward-axis branch with
`ax = -asin(t_y)` and `ay = atan2(t_x, t_z)`. Form `Mxy = My @ Mx`, add
`atan2(Mxy[0,1], Mxy[0,0])` to the input twist, then apply `Mxy @ Mz`.
All rotations here are standard right-handed active rotations. The basis map is
`(x, y, z)_NuMAD = (-y, x, z)_windIO`: windIO x points toward suction and y toward
the trailing edge. Thus a local airfoil point in windIO is
`(airfoil_y * chord, (airfoil_x - offset_ratio) * chord, 0)`.
The v2 twist follows the guide's positive rotation, not the legacy NuMAD negative
twist recipe. The v1 frame path retains that original recipe exactly.

The native v2 reference curves are retained explicitly on the definition rather
than enabling a global geometry switch. V1 retains its original geometry path.

## V2 surface and stations

The schema's `airfoils` description gives `rthick` precedence when both relative
thickness and spanwise airfoil positions are supplied, as in the official input.
V2 evaluates native `rthick` with PCHIP and interpolates master coordinates in
relative thickness, rather than interpolating by spanwise positions and scaling
legacy camber/thickness profiles. Masters must have distinct relative thicknesses
and bracket the requested distribution; unsupported ranges raise an error.

The common surface coordinate is normalized polyline arc length over the
**whole open airfoil**, as required by guide lines 82–90 and schema `surface`.
There is no authority there for the earlier sidewise normalization; that
implementation has been replaced. At every fraction s, all master coordinates
are evaluated at that same s using PCHIP, then interpolated pointwise in rthick.
Original source coordinates and open-TE endpoints are retained; the shape is
not normalized again by chord, thickness or separate pressure/suction lengths.

Only after constructing this continuous loft is its minimum-x LE landmark
located. The NuMAD representation samples the same loft on each side of that
landmark, retaining its fixed LE index without changing the surface definition.
`geometry.surface_fraction` publishes the whole-curve fractions of the open
profile samples (without the two appended TE midpoints); the LE fraction can
vary by station and is not forced to .5. This supports the official single-LE
masters, not arbitrary multi-lobed contours. NuMAD profiles run TE midpoint ->
pressure -> LE -> suction -> TE midpoint. Midpoints are added only after
interpolation, never included in a master spline. No sampled maximum-thickness
correction is applied.

Reference-axis length is the integral of the norm of the native x/y/z PCHIP
derivatives, split at all component knots (schema `reference_axis`). Native eta
is normalized **curvilinear length**, not z/tip-z; dimensional stations are
`eta * length`. The native reference curves remain parameterized by that eta,
without reparameterizing them as z curves. Chord, twist and dimensional
`section_offset_y` are evaluated directly on their native eta grids, also at
inserted chord knots; only then is offset divided by the evaluated chord.
These geometry checks do not calibrate any physics tolerance.

## T9: isolated source topology API (not yet a mesh path)

`Blade.read_yaml(...).windio2_topology` is available for v2 and `None` for v1.
It does not replace legacy keypoints/BOM/material flows. The public geometry-only adapter uses this topology directly; legacy
keypoints/BOM remain separate and are not a structural v2 route. No TE expansion or finite-width substitute is applied by this API.

- `source` is a recursively immutable snapshot (mappings and tuples) of the
  original parsed document; `source_sha256` hashes the original file bytes.
- `curves` contains frozen records with `identity=(kind, source_name, handle)`,
  `surface`, native `grid` and resolved `values`. Kinds are `anchor`, `layer`,
  `web`, and synthetic `perimeter` for the two TE-midpoint limits. Anchor
  references use the existing normalizer's resolver; alias identities survive.
  Skin curves have surface `skin`; web-local anchor/layer coordinates have the
  source web name and are **not** skin subdivisions.
- `curve.at(eta)` is linear on its native grid and returns `None` outside that
  domain, not an extrapolated or zero-filled boundary. Linear interpolation is
  the current explicit-arc reader convention, not a claim that the pinned
  schema prescribes a universal interpolation algorithm for every field.
- `event_stations` contains native boundary knots and analytic pairwise linear
  crossing events on each surface, plus 0 and 1. Coincident spans contribute
  their endpoints. T10 adds native thickness, orientation and explicit ply-count
  knots and layer/web span-domain endpoints. T11 must still choose mesh
  resolution. These events alone are not a conforming mesh.
- `section(eta)` accepts finite eta in [0,1] and returns frozen `points`,
  `intervals`, and `webs`. Points are sorted in **source** nd-arc direction;
  each exposes `nd_arc`, dimensional NuMAD `arc`, physical `xyz`, and all
  coincident source `identities`. Intervals are successive strictly nonzero
  source-arc pairs, not laminate ownership. At analytic crossing events the
  proven intersecting identities are unified without a spatial tolerance.
  TE 0/1 remain distinct topological points with the same physical midpoint.
  `webs` is a tuple of `(source_name, (start_point, end_point))`, present only
  where both native endpoint curves exist; there is no cap clipping.

Section queries regenerate **only Geometry** on an isolated definition snapshot
at the requested native eta: whole-curve loft, native frame and completed
midpoint perimeter all use the existing geometry construction. Physical points
use PCHIP on that completed dimensional arc, not interpolation of keypoint rows
or of spanwise coordinate samples. Repeated zero-length TE midpoint samples
are omitted only from the interpolator; source geometry is not expanded or
modified. Querying does not mutate the loaded blade. The T10 laminate extension
below supplies material ownership and web-local subdivision, but not mesh
connectivity or geometry/physics closure. T11/T12 must connect these queries to
the public mesh path without legacy overlap averaging, fixed-row ordering,
web clipping, or TE expansion.

### T10: source laminate cells for the mesh adapter

`section(eta).skin_cells` corresponds one-to-one with `section.intervals`.
`section(eta).web_cells` subdivides each active named web in its **own** normalized
coordinate, from its source start shell attachment (0) to its end attachment (1).
Web-local layer/anchor boundaries never subdivide the skin. Each frozen cell has:

- `surface`: `skin` or the original web name; `nd_bounds`: strictly increasing
  dimensionless bounds, with no minimum cell width or clipped boundary;
- `xyz`: two endpoint coordinates in metres (NuMAD axes); web points interpolate
  along the straight attachment-to-attachment segment;
- `layers`: frozen samples in original YAML list order, retaining `name`,
  `material_name`, and the complete immutable source `material` record (E/G in
  Pa, density in kg/m³, source ply thickness in metres);
- per-layer `thickness_m` and section-local `fiber_angle_deg`, and summed cell
  `thickness_m`. Explicit `n_plies` is retained as native interpolated metadata
  or `None`; continuum thickness is never converted to a rounded ply count.

Thickness and fiber orientation use linear interpolation on their **native**
span grids, with no extension beyond a field's source domain, just like the
explicit-arc query convention. Explicit `start_nd_grid`/`end_nd_grid` further
restrict layer and web support; endpoints are included. Zero thickness and
coincident start/end arcs contribute no finite-width laminate. Skin start > end
means a directed wrap across 1/0, not the complement or a full-perimeter band;
reversed web-local bounds raise an explicit error because a web is not periodic.
No legacy region averaging, clipping or fabricated reinforcement width is used.

Angles retain the schema's local-section convention: looking from the root,
positive fibers rotate towards the LE. The schema's zero-angle default applies
only when `fiber_orientation` is absent. This API does not invent stack-normal
orientation, individual physical plies, or an element-axis angle transformation;
the adapter must decide its axes explicitly. Current support is native 1D
thickness/orientation data exercised by the official source. Experimental 2D
thickness grids and missing dimensional thickness (including ply-count-only
layers) fail explicitly rather than being silently flattened or guessed.
The legacy MeshModel/BOM path is still unchanged; these cells are an isolated
query contract for T11/T12, not evidence of a conforming mesh or valid physics.

## T11 isolated raw skin/web mesh and restricted material adapter

`mesh_gen.windio2_mesh.generate_skin_mesh(topology, element_size=0.25,
eta_bounds=(0, 1))` is an isolated raw API, **not** the public BladeMesh path.
Only sizes 0.15–0.25 m are accepted. This entrypoint emits skin, including cells
whose source laminate is empty; the adapter must not invent properties for them.
`eta_bounds` supports a physical patch for inexpensive source regression checks.
Native events are mandatory stations; additional reference-length and dimensional
arc subdivisions provide a resolution target, not a maximum physical edge bound.

The mesher reconciles every cut on shared station rings before subdivision.
Strictly convex four-corner polygons retain their tensor-product structure:
each becomes four bilinear subquads. Polygons with collinear boundary cuts or
collapsed ends retain internal parameter-space triangle fans, whose triangles
are split into three genuine four-node quads. Both paths split every polygon
boundary edge at the same exact midpoint, preserving conforming interfaces.
No triangle or repeated-node quad is passed to the shell adapter.
Every new vertex is evaluated on the completed loft via
`topology.skin_points(eta, nd_arcs)`, not Cartesian chord interpolation. Only
source TE 0/1 identities are welded; there is no spatial tolerance welding,
TE expansion, band fabrication, cap clipping, or overlap averaging.
Nonpositive physical quads raise an error rather than being silently repaired.

Paths in the table are relative to `src/aeroelast/models/blade/numad/`.

**Can endpoint-only quads avoid the extension?** A regular four-corner strip can
remain one quad and avoid an interior eta. That does not give a general solution:
a source interval collapsing at a crossing forms a triangular chart region. With
vertices restricted to its two endpoint eta rows, a quad covering its apex either
repeats the sole apex node or has three vertices on the other row, giving a zero
corner Jacobian. Adding a point along a sloping side requires an interior eta.
Crossing a source boundary to borrow a node would violate coverage/ownership.
Thus endpoint-only construction is not a general remedy under the strictly
positive, boundary-conforming quad4 contract. This is a chart argument, **not**
a proof that every float64 Cartesian representation is impossible.

The two technically meaningful directions, neither proven complete or approved,
are:

1. **Exact/local chart identity plus locally evaluated geometry.** Keep topological
   event keys and normalized strip coordinates separate from final float64 XYZ;
   carry occupancy and attachment identity without float centroid/key collapse.
   Reuse the existing surface definition, with compensated/local evaluation where
   absolute float eta loses the displacement. This is narrower than replacing all
   geometry arithmetic, but still crosses all five boundaries above. Complexity
   is substantial numerical/API work; the unresolved proof is that final Cartesian
   rounding can retain distinct nodes and positive mapped Jacobians for required
   cells without source alteration. No such complete algorithm was established.
2. **Precision propagation through the v2 loft path.** Extend chart queries, native
   field/frame/airfoil evaluation, arc construction and intermediate coordinates;
   round to the existing FE coordinate contract only at an explicit final boundary.
   This reaches `objects/geometry.py` outside the current edit surface and cannot
   be achieved by changing an event tuple or NumPy dtype alone. Scope/cost is
   broader than direction 1, and it has the same final-coordinate feasibility
   obligation. No precision level or error band is selected here.

**Recommendation:** do not treat endpoint-only subdivision or a higher-precision
key as a demonstrated fix, and do not authorize a broad geometry rewrite from
these findings alone. There is **no approved complete representation solution**
in this unit. Retain fail-closed behavior. Any later implementation requires an
explicit decision on chart/section/metadata representation and the geometry edit
surface, not another full-mesh campaign on unchanged representation. No tolerance,
source-equivalence assumption or event merge follows from this closure.

### Raw skin/web connectivity

`mesh_gen.windio2_mesh.generate_mesh` adds quadrangulated web charts to the
same skin generator. It reuses exact skin node identities along each named
web's source start/end attachment, including coincident attachments of distinct
webs. There is no coordinate-tolerance welding. Web-local layer boundaries and
span dropoffs use the existing topology and laminate queries, not cap bands.
The raw result contains `nodes`, `elements`, aligned `cells`, `surfaces`,
`element_parameters`, `bases` and `attachments`. Each attachment key is

They are right-handed and checked against bilinear Jacobians at nine natural

Source layer angles are never copied directly into adapter-angle slots.

### S12: explicitly approved SONATA-derived material policy

This is an **adapter policy**, not a universal windIO convention. The pinned
schema (`normative-63dcad6/turbine_schema.yaml:554–568`) specifies degrees,
section-local reference and positive rotation towards LE viewed from root;
it does not specify physical layer-list direction or shell-normal signs.
The user selected policy A (S12) after the source investigation rather than
silently importing a consumer convention as another schema requirement.

Source proof is pinned to SONATA
[`c067e7a013661fbe9ea55945a29b5b150893ae82`](https://github.com/NLRWindSystems/SONATA/tree/c067e7a013661fbe9ea55945a29b5b150893ae82).
`classBlade.py:399–439,529–535` constructs its boundary from transformed outer
airfoil wires; `classCBM.py:187–206` passes it directly into segment 0.
`segment.py:223–266`, `layer.py:117–121` and `offset.py:136–144` build increasing
shell layers inward. Its airfoil-derived OML includes consumer interpolation
and TE-y recentering; it is not proof that SONATA preserves source coordinates
byte-for-byte. We reuse the existing v2 geometry, not those consumer alterations.

For webs, `converter_WT.py:291–388,439–496` constructs separate LE/TE filler
boundaries and routes face layers into adjacent segments. `web.py:44–51`,
`segment.py:136–146` and `offset.py:132,148–151` establish directed boundary
and right-side offset behavior: each skin grows away from filler into its
physical face. The converter resets its filler flag after the first TE record
and can overwrite later face-layer records; it is **not** general authority for
arbitrary source web lists. Its web `180/pi` angle multiplication also conflicts
with schema degrees and is not copied. Full excerpts, links and hashes are in
`logs/check/windio2/material-proof-source-trace.md` and `material-proof-inspect.stdout`.

Opt in with `generate_mesh(topology, with_materials=True, ...)`, or call
`map_mesh_materials(topology, raw_mesh)` to return a new mapped raw record.
`map_stack(cell, beam_axis, positive_normal, basis)` is the explicit single-cell
operation used by that path. It requires a right-handed element basis and an
explicit physical normal parallel to its normal, but permits either normal sign.

The policy is:

- **Longitudinal zero:** project the native local beam-axis unit tangent into
  the physical shell plane and normalize. Geometry's existing native PCHIP
  frame constructor supplies that axis and the local LE direction; the adapter
  does not duplicate the frame rotations. A degenerate beam projection fails.
  A constant-source-arc loft tangent is deliberately not substituted on tapered
  or twisted surfaces. This projection is the approved 3D extension of the
  longitudinal beam zero, not a rule proven by SONATA's 2D consumer.
- **Signed fibers:** if `l` is that projected zero, `n_face` is the physical
  outward face normal and theta is the unchanged source angle in degrees,
  `f = cos(theta)*l + sin(theta)*(n_face cross l)`. The signed face frames are
  explicit SONATA-derived adapter choices, not a claim that the schema defines
  shell-normal signs. In a straight untwisted NuMAD frame (+x LE, +y suction,
  +z span), positive skin angle points from span toward +x on suction and -x
  on pressure. Positive web angle points toward pressure on its LE face and
  toward suction on its TE face. Opposite element normals do not change these
  physical vectors; element angles are recomputed in each supplied basis.
- **Skin position/order:** source order is OML to inward. With outward element
  normal, the first source layer occupies `[-t_first, 0]`; subsequent layers
  continue inward. The physical OML is exactly z=0 and nodes stay there.
  Increasing-element-z order therefore reverses source order; opposite bases
  reverse it again without changing the physical stack.
- **Restricted web position/order:** each active mapped cell must contain exactly
  `[orthotropic LE skin, isotropic core, orthotropic TE skin]`. Unsupported,
  missing-core, extra-layer or incomplete active patterns raise
  `Web material mapping requires one orthotropic LE skin, isotropic core, orthotropic TE skin`.
  Orthotropic E must have three components, isotropic E is scalar. The unchanged
  web chart is the core-centre reference, not the total-stack mid-plane.
  The core occupies `[-t_core/2, t_core/2]` along the LE-directed normal;
  LE/TE skins grow from its positive/negative faces, respectively. There are no
  consumer flanges, filler-thickness floors or geometry shifts. This bounded
  interpretation covers the official input's triples, not arbitrary web layups.

Mapped `material_stacks` align with elements. Each stack exposes `reference`
(`outer_mold_line` or `web_core_center`), `physical_normal` (outward for skin,
toward LE for web), and layers sorted by **increasing element z**. Each mapped
layer exposes its unchanged `source` LayerSample, physical `fiber_vector`,
element `angle_deg`, and increasing `z_bounds_m` measured from the unchanged
reference nodes. `material_angles` follows this mapped layer order, not YAML
order. Empty skin stacks stay empty; no material is invented.
`midplane_offset_m` is the geometric stack-centre offset from those reference
nodes. In particular it is `-h/2` for outward-normal skin, not zero. This is
position metadata, **not** a request to relocate production OML nodes.

A future centered-shell consumer must explicitly account for this offset or
make a separately approved approximation. For centered CLT matrices and offset
c, the unchanged-reference matrices are `A_ref=A`, `B_ref=B+c*A`, and
`D_ref=D+2*c*B+c*c*A`. Tests use the existing Laminate/Ply consumer with this
explicit transformation; production contains no parallel constitutive engine.
Independent tensor-energy and two-point thickness integration oracles prove
nonzero-angle response, sign-changing orthotropic coupling, asymmetric centered
A/D preservation and B reversal, and physical-energy invariance under opposite
right-handed bases. OML-reference energy is checked separately so centering
cannot silently pass as physical preservation. Source records, geometry arrays
and the official YAML remain unchanged.

The public geometry-only adapter retains this bounded raw material proof and
its physical offsets; it does not convert them to structural properties.
Full-blade mesh quality is rejected as recorded above, and final T8 independent
verification remains pending. No physics run, tolerance change or universal
windIO stacking claim is authorized.
