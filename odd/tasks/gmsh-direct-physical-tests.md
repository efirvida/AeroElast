# gmsh v2 mesher: direct physical tests vs BeamDyn and ElastoDyn (IEA-15, IEA-22)
Contrast the adopted gmsh mesher (gmsh_skin.py with the merge criterion) against OpenFAST BeamDyn (static, free vibration) and ElastoDyn (blade modes) on the official unmodified decks. Follows odd/tasks/gmsh-validation-15-22.md (L21-L25). Runner: scripts/aeroenv.sh; SLURM --ntasks only; unified FEM = logs/check/gmsh_fem_webs/run_fem.py.

- L9 CORRECTION of the IEA-22 ElastoDyn 2F (-69 %), user concern verified by calculation, not by assertion. Rayleigh quotient f^2 = int EI (phi'')^2 / int m phi^2 with the ElastoDyn blade file's own mass and flap stiffness tables and its polynomial shapes (script in the session; BlFract/BMassDen/FlpStff/EdgStff, 59 stations for the 22, 50 for the 15): mode 1 flap 0.3983 Hz (22) and 0.5429 (15) against ElastoDyn 0.3980 and 0.5432; edge 0.5422/0.7414 against 0.5434/0.7403; 'flap 2' 3.4244 Hz (22) against ElastoDyn 3.3531 and 1.6075 (15) against 1.6118. So the OpenFAST run reproduces what the file implies and the deck conversion is NOT the cause. The cause is the shape: the IEA-22 BldFl2Sh polynomial changes sign 3 times inside the blade (the 15's changes sign once, as a second mode must). It is the shape of the 4th flapwise mode (3 interior nodes), and the 3.35-3.42 Hz it gives is the 4th flap, whose shell value is 3.5458 Hz (ElastoDyn 5.7 % below it). That is a defect (or an upstream convention) of the IEA-22 ElastoDyn blade file, not a disagreement between two methods on the 2nd mode; the ElastoDyn parked comparison for the 22 therefore has only 1F and 1E (-5.9 %, -5.8 %). The earlier statement 'poor Rayleigh-Ritz shape inflates the frequency' was an unverified guess for the cause and is replaced by this.
